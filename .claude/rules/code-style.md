# コードスタイルルール

## 命名規則

- **変数・関数**: キャメルケース（`myVariable`, `getUserById`）
- **クラス・型**: パスカルケース（`UserService`, `ApiResponse`）
- **定数**: アッパースネークケース（`MAX_RETRY_COUNT`, `DEFAULT_TIMEOUT`）
- **ファイル名**: ケバブケース（`user-service.ts`, `api-client.py`）
- **略語は避ける**: `usr` → `user`, `btn` → `button`（広く普及しているもの除く）

---

## 関数・メソッド

- **単一責任**: 1つの関数は1つのことだけを行う
- **長さの目安**: 30行以内を目指す。超える場合は分割を検討する
- **引数の数**: 3つ以内を目安にする。多い場合はオブジェクト渡しにする
- **副作用を明示**: 副作用がある関数は名前で示す（`fetchUser`, `saveRecord`）
- **早期リターン**: ネストを減らすために早期リターンを積極的に使う

---

## コメント

- **なぜ（Why）を書く**: コードから読み取れる「何を（What）」は書かない
- **TODO コメント**: `TODO:` に担当者・日付・チケット番号を付ける
  ```
  // TODO(username 2026-04-04 #123): キャッシュ実装後に削除
  ```
- **魔法の数値**: リテラルをそのまま使わず、名前付き定数にする

### コメントを書くべき場面

- **公開関数・メソッド**: すべての公開関数・メソッドにドキュメントコメントを書く。何をする関数か（目的）・引数の意味・戻り値を記載する
  ```
  /**
   * ユーザーIDに対応するユーザーを取得する。
   * 該当ユーザーが存在しない場合は null を返す。
   *
   * @param userId - 検索対象のユーザーID
   * @returns ユーザーオブジェクト、または null
   */
  ```
- **公開クラス**: クラスの責務（何を表すか・何をするか）をドキュメントコメントで説明する
  ```
  /**
   * 注文の生成・キャンセル・金額計算を担うドメインエンティティ。
   */
  ```
- **ファイルヘッダー**: モジュール・ファイルの責務を1〜3行で記載する（自明なファイルは省略可）
  ```
  // ユーザー認証に関するユーティリティ関数群。JWT の生成・検証を提供する。
  ```
- **複雑なアルゴリズム・非自明なロジック**: 処理の流れや意図を説明するインラインコメントを書く
- **ビジネスルールの根拠**: 仕様書を見ないとわからない条件・判断の理由を記載する
  ```
  // 法律上、18歳未満はアルコール商品を購入できない（酒税法第9条）
  if (age < 18) return false
  ```
- **意図的な非自明な実装**: パフォーマンス等の理由で一見不自然に見えるコードはその意図を説明する
  ```
  // n+1を避けるため、ここで一括取得してMapに変換する
  ```
- **副作用・依存関係の警告**: 呼び出し順序や副作用に注意が必要な箇所は警告コメントを書く
  ```
  // この関数はDB接続を閉じる。呼び出し後は再接続が必要
  ```
- **既知の問題・制限事項**: 意図的に残している制約や将来対応予定の限界を記載する
  ```
  // 現状は最大1000件まで対応。件数増加時はページネーション実装が必要
  ```
- **長い処理のフェーズ分割**: 複数ステップある処理は区切りコメントで構造を明示する
  ```
  // Step 1: 入力バリデーション
  // Step 2: ドメインオブジェクト生成
  // Step 3: 永続化
  ```

## フォーマット

- **インデント**: スペース2つ（Tabは使わない）
- **行末の空白**: 禁止
- **末尾改行**: ファイルの末尾は改行1つ
- **1行の長さ**: 120文字以内を目安にする
- **空行**: 論理的なブロック間に1行の空行を入れる

---

## インポート・依存関係

- **未使用インポートは禁止**
- **インポートの順序**: 標準ライブラリ → 外部ライブラリ → 内部モジュール（間に空行）
- **循環依存は禁止**: アーキテクチャを見直す

---

## エラーハンドリング

- **エラーを握りつぶさない**: `catch` 内で何もしない実装は禁止
- **エラーメッセージ**: 何が起きたか・どこで起きたかを含める
- **想定外の入力**: システム境界（APIエンドポイント・ユーザー入力）でのみバリデーションする

---

## コードの重複

- **3回以上同じパターンが出たら共通化を検討する**
- **ただし過剰な抽象化は避ける**: 1〜2箇所の重複は許容する
