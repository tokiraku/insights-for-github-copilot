# フィードバックテンプレート

レビュー結果を出力する際は以下のテンプレートを使用する。

---

## コードレビュー結果: `<対象ファイル/モジュール名>`

### サマリー

| 優先度 | 件数 |
|--------|------|
| 🔴 必須修正 | N件 |
| 🟡 推奨 | N件 |
| 🔵 提案 | N件 |

---

### 🔴 必須修正

> セキュリティ脆弱性・バグ・データロス・本番障害リスクに該当する問題。リリース前に必ず対応。

#### [CR-001] `<問題タイトル>`

- **場所**: [`ファイル名:行番号`](ファイル名#L行番号)
- **分類**: セキュリティ / バグ / データロス（該当するものを記載）
- **問題**:  
  具体的な問題の説明。なぜ危険なのかを明示する。
- **リスク**:  
  この問題が引き起こす具体的なリスク（例: SQLインジェクションによるDB全件取得）
- **修正案**:

  ```<言語>
  // 修正前
  <問題のあるコード>

  // 修正後
  <修正したコード>
  ```

---

### 🟡 推奨

> 保守性・可読性の低下、潜在的なバグ、ベストプラクティス違反。次のスプリントまでに対応を推奨。

#### [CR-002] `<問題タイトル>`

- **場所**: [`ファイル名:行番号`](ファイル名#L行番号)
- **分類**: 可読性 / 保守性 / ベストプラクティス（該当するものを記載）
- **問題**:  
  問題の説明と影響範囲。
- **改善案**:

  ```<言語>
  // 改善後のコード例
  ```

---

### 🔵 提案

> パフォーマンス改善・リファクタリング・将来の拡張性向上。余裕があれば対応。

#### [CR-003] `<提案タイトル>`

- **場所**: [`ファイル名:行番号`](ファイル名#L行番号)
- **提案**:  
  改善の提案内容と期待されるメリット。

---

### 総評

全体的なコード品質の評価（良い点・改善すべき点）を2〜3文で記載。
指摘が0件の軸があれば「品質・可読性: 問題なし」のように明示する。

---

## 使用上の注意

- **[CR-XXX]** の番号は連番とし、優先度をまたいで通し番号にする
- 指摘事項がない優先度のセクションは省略する
- コードスニペットは実際のコードから引用し、架空のものを作らない
- 修正案がない場合は「修正方針」として方向性だけ示す
