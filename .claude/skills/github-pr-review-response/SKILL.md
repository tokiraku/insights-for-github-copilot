# GitHub PRレビューコメント対応スキル

## 概要

GitHub PRに付いたレビューコメントに対して、以下を順番に実施する。

1. PRコメントを確認する
2. 対応の必要性を確認する
3. 結果をユーザーに通知する（対応案、返信コメント案）
4. 対応の要否をユーザーに確認する
5. ユーザー承認を得られたものを対応する
6. 対応内容をコミット、プッシュ、コメント返信する

本スキルの最重要ルールは、**各ゲートでユーザーの明示的承認があるまで次へ進まない**こと。

## 実行手順

### Step 1: PRレビューコメントの取得

**まず GitHub MCP サーバーの有効化を試みる。** `mcp_github_*` ツールが見当たらない場合は、Claude Code の MCP 設定（`/mcp` コマンドまたは設定ファイル）で GitHub MCP サーバーが有効になっているか確認し、有効化するようユーザーに案内する。

MCPが利用可能なら、GitHub APIを直接叩かずにMCP経由で取得する。

1. PRメタ情報を取得
2. レビューコメントと通常コメントを取得
3. 既に解決済み/古いコメントを区別

推奨ツール:
- `mcp_github_pull_request_read`（`get`, `get_review_comments`, `get_comments`, `get_files`）

### Step 2: 対応必要性の判定

各コメントを以下のカテゴリで分類する。

- `required`: マージ前に修正が必要（バグ、回帰、セキュリティ、CI失敗に直結）
- `optional`: 改善提案として有益だが必須ではない
- `no-action`: 既に反映済み、誤解、スコープ外、重複

判定時は必ず根拠を1行で残す。

### Step 3: ユーザーへの報告（実装前）

次の3点を必ず提示する。

1. コメントごとの判定結果（`required`/`optional`/`no-action`）
2. 実装する場合の対応案（変更方針、影響ファイル、テスト観点）
3. GitHubに返す返信コメント案（日本語またはPRの言語に合わせる）

### Step 4: 実装可否の確認（承認ゲートA）

ユーザーに「どの項目を実装するか」を確認する。

- 承認がない項目は実装しない
- 不明瞭な指示は再確認する

### Step 5: 承認済み項目のみ実装

承認済み項目に限定して、最小差分で変更する。

1. コード修正
2. 必要なテスト追加または既存テスト更新
3. テスト実行（可能な範囲）
4. 変更内容サマリー作成

### Step 6: コミット/プッシュ/返信の確認（承認ゲートB）

以下を実行する前に、必ずユーザー承認を得る。

- コミット
- プッシュ
- GitHubへの返信コメント投稿

承認依頼時に提示する情報:

1. コミットメッセージ案
2. プッシュ先ブランチ
3. 実際に投稿する返信コメント本文

### Step 7: 承認後に実行

承認が得られた場合のみ実行する。

1. `git add` / `git commit`
2. `git push`
3. レビュー返信投稿

返信投稿の推奨ツール:
- 既存レビューコメントへの返信: `mcp_github_add_reply_to_pull_request_comment`
- PR全体への補足コメント: `mcp_github_add_issue_comment`
- レビュー全体として送る場合: `mcp_github_pull_request_review_write`

## 承認ルール（必須）

- ユーザー承認なしでコード変更しない
- ユーザー承認なしでコミットしない
- ユーザー承認なしでプッシュしない
- ユーザー承認なしでGitHubへ返信しない

## 出力フォーマット

### 1. 判定レポート

```md
## PRレビューコメント対応案: <owner/repo>#<PR番号>

### required
1. <コメント要約>
- 理由: <なぜ必須か>
- 対応案: <実装方針>
- 返信コメント案: <投稿文案>

### optional
1. <コメント要約>
- 理由: <任意と判断した根拠>
- 対応案: <実施する場合の方針>
- 返信コメント案: <投稿文案>

### no-action
1. <コメント要約>
- 理由: <不要と判断した根拠>
- 返信コメント案: <投稿文案>
```

### 2. 承認確認テンプレート（実装前）

```md
以下の対応を実装してよいですか？

1. <項目A>
2. <項目B>

実装不要の項目があれば番号で指定してください。
```

### 3. 承認確認テンプレート（コミット/プッシュ/返信前）

```md
以下を実行してよいですか？

1. コミット
- メッセージ案: <message>

2. プッシュ
- ブランチ: <branch>

3. GitHub返信コメント投稿
- 投稿内容:
	<comment body>
```

## 注意事項

- **GitHubへ投稿するコメントは必ず日本語で書く**（コード例・ファイルパス・技術用語は除く）
- 無断で作業を先に進めない。必ず承認ゲートを通過する
- 返信コメントは事実ベースで簡潔に書き、感情的な表現を避ける
- 反論が必要な場合は、代替案と技術的根拠をセットで提示する
- 既に対応済みの内容には、該当コミットや差分を示して説明する
- 変更の根拠と判断ログを残し、後から追跡できる状態にする
