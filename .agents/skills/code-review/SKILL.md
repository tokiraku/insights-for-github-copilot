# コードレビュースキル

## 概要

コードを3つの軸（品質・セキュリティ・設計）で分析し、**優先度別**にフィードバックを整理して出力する。

## 実行手順

### Step 1: 対象コードの収集

ユーザーが指定したファイル/ディレクトリを読み込む。未指定の場合は現在のワークスペースのメインコードを特定する。

- `read_file` または `grep_search` でコードを収集
- 大規模なコードベースは `search_subagent` を使って関連ファイルを特定

### Step 2: 3軸での分析

[品質・可読性チェックリスト](./references/quality-checklist.md) と [セキュリティ・設計チェックリスト](./references/security-design-checklist.md) を参照して、各観点でコードを分析する。

**分析軸:**
1. **コードの品質と可読性** — 命名、関数の単一責任、重複、可読性、コメント
2. **セキュリティ** — OWASP Top 10、入力検証、認証・認可、シークレット管理
3. **設計** — 依存関係、結合度、拡張性、エラーハンドリング

### Step 3: 優先度分類

各指摘事項を以下の基準で分類する：

| 優先度 | 基準 | 対応期限の目安 |
|--------|------|----------------|
| 🔴 **必須修正** | セキュリティ脆弱性、バグ、データロス、本番障害リスク | リリース前に必ず対応 |
| 🟡 **推奨** | 保守性・可読性の低下、潜在的なバグ、ベストプラクティス違反 | 次のスプリントまでに対応 |
| 🔵 **提案** | パフォーマンス改善、リファクタリング案、将来の拡張性 | 余裕があれば対応 |

### Step 4: フィードバック出力

[フィードバックテンプレート](./references/feedback-template.md) に従って出力する。

---

## 注意事項

- **実装済みの動作するコード**が対象。未完成コードは前提を明示してレビューする
- 指摘は**具体的な行/関数**を示す。抽象的な指摘は避ける
- 修正案は**コードスニペット**で示すことを優先する
- ユーザーのメモリに記録されたプロジェクト規約があれば優先的に適用する
