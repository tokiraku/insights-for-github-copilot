# セキュリティ・設計チェックリスト

## セキュリティ (OWASP Top 10 準拠)

### 入力検証・インジェクション対策 (A03)

- [ ] ユーザー入力をすべてバリデーションしているか
- [ ] SQLクエリはプレースホルダー/ORM を使っているか（文字列連結は NG）
- [ ] HTML出力はエスケープしているか（XSS対策）
- [ ] OSコマンド実行時に入力を含めていないか
- [ ] パスを構築する際にディレクトリトラバーサルを防いでいるか

### 認証・認可 (A01, A07)

- [ ] 認証チェックをバイパスできる経路がないか
- [ ] 権限チェックをクライアントサイドのみで行っていないか
- [ ] セッション固定攻撃への対策があるか
- [ ] パスワードは安全なハッシュアルゴリズム（bcrypt, Argon2 等）で保存しているか

### シークレット管理 (A02)

- [ ] APIキー・パスワード・トークンをソースコードにハードコードしていないか
- [ ] `.env` ファイルや環境変数から読み込んでいるか
- [ ] シークレットがログに出力されていないか
- [ ] デバッグ用の認証バイパスが残っていないか

### 暗号化 (A02)

- [ ] 機密データの転送はTLS/HTTPSを使っているか
- [ ] 非推奨の暗号アルゴリズム（MD5, SHA1, DES）を使っていないか
- [ ] 乱数生成は暗号論的に安全な関数を使っているか

### エラー処理・情報漏洩 (A09)

- [ ] スタックトレースをそのままユーザーに返していないか
- [ ] 内部パス・バージョン情報・DB情報をレスポンスに含めていないか
- [ ] エラーログに個人情報（PII）を含めていないか

### 依存関係 (A06)

- [ ] 既知の脆弱性を持つライブラリを使っていないか
- [ ] 依存関係のバージョンを固定しているか（ロックファイル）

---

## 設計

### 単一責任・凝集度

- [ ] クラス/モジュールが1つの責任に集中しているか
- [ ] 関係のない機能が同一モジュールに混在していないか

### 結合度

- [ ] モジュール間の依存が最小限か
- [ ] 具象クラスではなくインターフェース/抽象に依存しているか（DIP）
- [ ] 循環依存が発生していないか

### 拡張性・変更容易性

- [ ] 機能追加時に既存コードを修正しなくて済む設計か（OCP）
- [ ] 設定値がハードコードされず外部化されているか
- [ ] ストラテジーパターン等で振る舞いを差し替えられるか

### データ管理

- [ ] 不変オブジェクト（Immutable）を適切に使っているか
- [ ] 共有可変状態（Shared Mutable State）を最小化しているか
- [ ] データクラスとロジックが適切に分離されているか

### 非同期・並行性

- [ ] 競合状態（Race Condition）が発生しないか
- [ ] デッドロックが発生しないか
- [ ] 非同期処理のエラーハンドリングが漏れていないか
- [ ] Promise/async-await の連鎖が適切に処理されているか

### パフォーマンス

- [ ] ループ内でN+1クエリが発生していないか
- [ ] 不必要なデータを大量に取得していないか（過剰フェッチ）
- [ ] キャッシュが適切に活用されているか
- [ ] メモリリークが発生する構造になっていないか
